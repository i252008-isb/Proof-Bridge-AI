# Demo Guide — ProofBridge AI

The offline demo walks a synthetic customer-support case through every
stage of the investigation. No real customer data, no API keys, no
network.

## Run it

```bash
PROOFBRIDGE_DEMO_MODE=true python examples/run_demo.py
```

## The scenario

A customer bought **SonicWave Pro Wireless Headphones**; the left ear cup
arrived cracked; the customer requests a refund. Synthetic fixtures are
generated into `examples/demo_data/`: receipt (text + scan image),
product listing, seller chat, delivery record, refund policy, and a
drawn "damaged photo" (Pillow).

## Stages

| # | Stage | What you see |
| --- | --- | --- |
| 0 | Fixtures | Synthetic files written to `examples/demo_data/` |
| 1 | OCR | Receipt scan image → text. Without Tesseract the stage prints the honest `[OCR UNAVAILABLE]` notice and continues |
| 2 | Ticket understanding | Issue type `damaged_product`, claims labeled `unverified` (source `customer_ticket`) |
| 3 | Evidence extraction | Batch processing per item: summaries + deterministic facts (order number, date, amount) |
| 4 | Vision AI | `status="mock"` with the mock limitation — no fabricated observations |
| 5 | Policy extraction | Three rules with verbatim source quotes (`return_window`, `damaged_on_arrival`, `proof_requirement`) |
| 6 | Semantic matching | Claim↔evidence relevance scores (labeled mock embeddings) |
| 7 | Pipeline | Rule assessments (`met` / `partially_met`), missing information, recommendation `request_more_information` — honest, because the mock vision cannot confirm the damage |
| 8 | Report | Full `InvestigationReport` JSON written to `examples/demo_data/demo_report.json` |
| 9 | DEMO SIMULATION | A clearly labeled scripted vision provider shows what genuine vision output would add: `refund_recommended`. This stage is explicitly labeled a simulation — not real model output |

## Labeling rules honored by the demo

- Mock LLM/vision/embeddings output is labeled on every line that uses it.
- The recommendation in stage 7 reflects the mock limitation; the happy
  path is only shown in the labeled simulation stage.
- Timestamps are never invented: the timeline only contains supplied
  dates.
- The final-decision notice is printed: an authorized human support agent
  makes the final decision.

## FastAPI example

```bash
uvicorn examples.fastapi_integration:app --reload
# http://127.0.0.1:8000/docs
```

Endpoints: create case (ticket), extract claims, upload evidence (vision
runs automatically for images), upload policy, supply order information,
run analysis, retrieve report.

## Sample report

`docs/ai/sample_report.json` is regenerated by
`python docs/ai/generate_sample_report.py`, which runs the demo scenario
through the clearly labeled scripted vision simulation. The report's
`limitations` array carries a provenance note saying it is not the output
of a real vision model. Regenerate it after changing report schemas.
