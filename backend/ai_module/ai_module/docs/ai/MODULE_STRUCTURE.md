# Module Structure — ProofBridge AI

File-by-file map of the `proofbridge_ai` package.

## Package root

| File | Contents |
| --- | --- |
| `__init__.py` | Public API: facade functions, `Settings`, all schemas, exceptions, constants. Version `0.2.0`. |
| `config.py` | `Settings` (pydantic-settings, `PROOFBRIDGE_` prefix), `get_settings()` (cached), cross-field validators (threshold ordering, demo mode). |
| `schemas.py` | Complete data contract: enums, ticket/evidence/policy/vision/conversation/cross-source models, `SupportCaseAnalysisResult`, `InvestigationReport` (schema version `2.0`), constants (`REPORT_TITLE`, `FINAL_DECISION_NOTICE`, `CENTRAL_PRINCIPLE`). |
| `exceptions.py` | `ProofBridgeAIError` hierarchy (see ERROR_HANDLING.md). |
| `logging_utils.py` | Structured logger factory (`get_logger`); logs IDs, never secrets or full documents. |

## providers/

| File | Contents |
| --- | --- |
| `base.py` | `BaseLLMProvider` (`chat`, `generate_json`), `BaseEmbeddingsProvider` (`embed_texts`, `embed_query`), `BaseVisionProvider` (`analyze_images`, `analyze_image`), `VisionImage` dataclass. |
| `mock_providers.py` | Deterministic offline stand-ins for all three provider kinds; `is_mock=True`. |
| `openai_providers.py` | OpenAI-compatible clients: JSON-mode generation with retries/timeouts, embeddings, multimodal vision (base64 images). |
| `factories.py` | `get_llm_provider`, `get_embeddings_provider`, `get_vision_provider` — cached per configuration; demo mode forces mocks. |

## services/

| File | Contents |
| --- | --- |
| `ticket_analyzer.py` | `extract_ticket_claims`: complaint → `TicketAnalysisResult` (issue type, requested resolution, UNVERIFIED claims). Backend-supplied claims used verbatim; LLM dates verified against the complaint text. |
| `evidence_extractor.py` | `extract_evidence`, `extract_evidence_batch`: uploads → `EvidenceItem`s (extracted text, summary, deterministic facts, warnings); per-item error isolation; category inference. |
| `document_extractor.py` | `extract_document`, `extract_document_text`: PDF (pymupdf), DOCX, text files, images via OCR; normalization and size/type validation. |
| `ocr_service.py` | `is_ocr_available`, `extract_text_from_image`: Tesseract wrapper with availability checks. |
| `file_validation.py` | File type detection, size/page/pixel limits, content-type handling. |
| `text_normalizer.py` | Whitespace/control-char normalization and `truncate_text` used by summaries and report excerpts. |
| `vision_analyzer.py` | `analyze_visual_evidence`: photo inspection / image comparison; mock → `status="mock"`; unreadable/provider failure → `status="failed"` with limitations; standard vision limitations appended. |
| `product_analyzer.py` | `extract_purchase_information` (and payment/order helpers): receipt facts (seller, product, model, order number, date, price, currency, quantity) — only values present in the document. |
| `conversation_analyzer.py` | `analyze_conversation`: chat export → messages with speakers, refund promises, warnings. |
| `policy_extractor.py` | `extract_refund_policy`: policy text/document → rules with verbatim `source_quote` (unverifiable quotes dropped). |
| `policy_evaluator.py` | `evaluate_refund_policy`: rule-by-rule assessment (return window, damage, proof requirements, informational); missing information returned separately. |
| `similarity_engine.py` | `compare_support_evidence`: claim↔evidence relevance scores (embeddings or labeled lexical approximation). |
| `cross_source_verifier.py` | `verify_cross_source`: order ID/product/date/price/currency/quantity consistency across ticket, receipts, order data, payments, chats; factual contradictions; receipt confirmation gaps. |
| `support_case_analyzer.py` | `analyze_support_case` / `arun_support_case_analysis`: the 15-step orchestration, claim assessment (order/date/damage claims vs document facts), recommendation engine, source summary. |
| `report_generator.py` | `generate_investigation_report`: structured report from the analysis (verbatim findings, evidence inventory, OCR findings, timeline from supplied timestamps only, neutral summary, fallback report). |

## integration/

| File | Contents |
| --- | --- |
| `facade.py` | `ProofBridgeAIFacade` (settings-bound methods), `get_facade()` (cached), module-level functions re-exported from services (contract = implementation). |

## examples/

| File | Contents |
| --- | --- |
| `run_demo.py` | Offline end-to-end demo (synthetic headphones case) with visibly labeled stages. |
| `fastapi_integration.py` | Runnable FastAPI reference for Person 2 (in-memory repository stand-in). |
| `demo_data/` | Synthetic fixtures generated by `run_demo.py` (receipt, listing, chat, delivery, policy, photos, report JSON). |

## tests/

| File | Contents |
| --- | --- |
| `conftest.py` | Env isolation per test, demo settings fixture, generated sample documents. |
| `_fakes.py` | Scripted `FakeLLMProvider` / `FakeVisionProvider` (no network). |
| `test_*.py` | Per-service suites plus `test_support_case_analyzer.py` (pipeline), `test_scenarios.py` (scenarios A–J), `test_facade.py`, `test_report_generator.py`. |
